# Format Capabilities R1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give PicoSerDe one testable source of truth for "which shape can which wire format express", make every dropped member report a diagnostic, and change **zero bytes** of generated code.

**Architecture:** Two internal tables replace 25 scattered `if (formatTag == ...)` checks. `FormatFacts` records what the wire format can express (stable; drives the matrix, the diagnostics and validation). `EmitCoverage` records what today's generators can actually emit (transient scaffolding, deleted in R2 when the shared pipeline lands). Generators receive the tables instead of a format string, so a bare `formatTag == "json"` stops compiling. Detection paths that today drop a member with no report are wired to a real diagnostic.

**Tech Stack:** C# 13 / .NET 10, Roslyn incremental source generators, `shared/Gen` (linked into all 5 generators), TUnit + Microsoft Testing Platform, CSharpier.

**Spec:** `docs/superpowers/specs/2026-10-25-format-capabilities-design.md`

## Global Constraints

- **R1 must not change generated bytes.** Every task's verification includes the byte-diff gate from Task 2; new diagnostics are allowed, new/removed generated code is not.
- Format facts come from the spec's §3.2 table, which was measured with independent implementations (`tomllib`, PyYAML) — do not re-derive them from the current code.
- `FormatCapabilities` and both tables are **`internal`**: `api/*.public.txt` must not change. Any diff there is a bug in this release.
- Diagnostics: ids `PICOSERDE001`–`PICOSERDE005` are a public contract; do not renumber. New messages keep a stable greppable prefix.
- Never silence: no `continue` may skip a member without adding to a skip list that is actually reported (R2).
- Build with `-m:1` (`dotnet build PicoSerDe.slnx -c Debug -m:1`); parallel builds have crashed with `MSB4166`.
- Zero warnings: `dotnet build` must end at `0 Warning(s) 0 Error(s)`. Test projects that deliberately contain unrepresentable models add `PICOSERDE004` (and after Task 5, possibly `001`) to `NoWarn`, following `tests/PicoSerDe.Integration.Tests/PicoSerDe.Integration.Tests.csproj:13`.
- Format changed files with `dotnet csharpier format <files>` (run `dotnet tool restore` once).
- No test counts in any document; state the command, not the total.

## Review Focus

The spec is a vision document; its silence is not permission. These are the failure modes most likely to bite, most likely first, each pinned by a test in the task that owns the code:

1. **A generated serializer that compiles but drops a member** — the shapes in Task 2's corpus are the only guard; if a rewire (Task 3) flips one drop condition, only the byte diff catches it.
2. **A capability read that silently changes behaviour** — `FormatFacts` values copied wrong (e.g. YAML marked as unable to hold null) would drop data that the format can express. Task 1's table test compares facts to the spec's §3.2 verbatim.
3. **Diagnostics that multiply** — reporting `PICOSERDE001` from three sites (Task 5) can emit the same member repeatedly; Task 5 asserts one diagnostic per (type, member).
4. **A message that misleads** — the current text says "cannot be represented by this format" for shapes the format can represent (Task 7 must distinguish fact from debt).
5. **A public API change sneaking in through an internal type** — `FormatCapabilities` leaking into a `public` signature would force an `x` bump; Task 4's architecture test plus the `api/*.public.txt` diff gate covers it.

  ```csharp
  internal readonly record struct FormatFacts(
      string Tag,
      bool CanWriteNull,          // format has a null literal at all
      bool CanHoldNullInSequence, // sequence elements may be null
      bool CanNestContainers,     // list-of-list / object-in-object
      bool CanHoldObjectList,     // List<Dto> as a member
      bool CanHoldExtendedSet,    // HashSet/Queue/Stack/... as a member or element
      bool CanBeRecursive,        // arbitrarily deep self-reference
      bool CanHoldArrayOfTables,  // TOML [[Table]]
      bool DictKeysAreStringOnly);

  internal readonly record struct EmitCoverage(
      bool EmitsNullInSequence, bool EmitsNestedCollections, bool EmitsObjectList,
      bool EmitsExtendedSet, bool EmitsRecursion, bool EmitsArrayOfTables);

  internal static class FormatCapabilities
  {
      public static FormatFacts Facts(string tag);   // "json"|"msgpack"|"toml"|"yaml"|"ini"
      public static EmitCoverage Coverage(string tag);
      public static IReadOnlyList<FormatFacts> All { get; }
  }
  ```
