# v2026.16.0 — release notes

## 0. One sentence — what this release is

**A polymorphic type reached as a member kept neither its tag nor its data in TOML, YAML or MessagePack**,
and two other paths accepted what their own sibling path rejected. All three are behaviour changes, so this
is `x+1` even though the public API is untouched.

The rest is fences: a third ablation wave put 52 mutations through the DOM layer, the streaming paths, the
anonymous/polymorphic generators and the attribute pipeline, and found 22 protections that nothing watched.

## 1. `H5` — the serious one: polymorphic members lost their data

| | Before | Now |
|---|---|---|
| JSON | `{"$type":"cat","Id":3,"Lives":9}` | unchanged (it was correct) |
| **MsgPack** | `{Id:3}` — no tag, no `Lives` | tag + derived members |
| **TOML** | `[Star]` with `Id = 3` | tag + derived members |
| **YAML** | `Star:` with `Id: 3` | tag + derived members |

Deserialising gave back the **base** type. No diagnostic anywhere. MessagePack was correct for list
**elements**, which is exactly why the defect survived: the same type worked in one position and silently
lost data in another.

Three different causes behind one symptom:

- **TOML and YAML** inner helpers had no polymorphic dispatch at all — the symbol does not appear in either
  file.
- **MessagePack** had one, but resolved it against the **unmerged** type list rather than the merged list
  JSON uses.

**Migration:** documents written by TOML/YAML/MessagePack before this release do not contain the
discriminator, so they still deserialise to the base type — they cannot be recovered. Re-serialise from
the objects you still hold.

## 2. Streaming accepted what the byte path rejected

`DeserializeFromStreamAsync` materialised `{"N":1} 7` and discarded the `7`, while the same bytes through
`Deserialize` threw. The README states both paths share semantics.

The gate went into the **shared** streaming loop once, rather than into each format's delegate — a per-format
copy would be the fifth place where the two paths can drift apart. The four formats do not need the same
mechanism, and the report measures why: JSON and MessagePack documents have a **closing byte**, so the loop
must answer "what is behind it"; TOML/YAML/INI have none, and their lexer already fails on a stray line.

## 3. A negative DOM index meant "the first element"

`RootElement[-1]` fell through the indexer's loop and returned **element 0** — silently, and asymmetrically
(an empty array threw `IndexOutOfRangeException`). It now throws, like the out-of-range case always did.

## 4. The DOM layer was the least-fenced area in the repo

Nine of fifteen mutations there went unnoticed, and most returned a **wrong value** rather than failing:

| Call | Returned |
|---|---|
| `RootElement[3]` on a 3-element array | an `Undefined` element |
| `GetString()` on a number | `"42"` |
| `GetBoolean()` on `42` **and** on `null` | `false` |
| integer indexer on an **object** | a member's value |
| `GetArrayLength()` on an **object** | the member count |
| `TryGetInt32` on the string `"42"` | `true`, `42` |
| `GetDouble` without `InvariantCulture`, under de-DE | **314** for `3.14` |
| `GetInt32` without `checked` | `1` for `4294967297` |

All eight are now asserted, each proven by re-applying its mutation.

## 5. Also fenced

- **Attribute pipeline**: an explicit `[XxxKey]` beating a class-level `[XxxCamelCase]`; a format-level
  `[XxxIgnore]` surviving a per-property `Condition`; `WhenWritingDefault` still writing a non-default value;
  and an attribute from **another namespace** not being honoured because it shares a name. The first of those
  exists **twice** — property pipeline and anonymous-type handler — so it is pinned twice; that duplication
  is the same shape as the `[GenerateSerializer]` defect fixed in 2026.14.0.
- **Streaming**: JSONL blank lines, a final line without a newline, a truncated array (which **looped
  forever** when unguarded), a cancelled token, and a struct DTO's trailing data.

## 6. Recorded, not done

| Item | Why it is not a fix |
|---|---|
| `RegisterCustom<T>` exists for JSON and MessagePack only | a feature gap, not a defect; TOML/YAML/INI would each need the whole registry |
| TOML **table** redefinition (`[T]` twice) still accepted | invalid TOML, but a separate dedupe from the duplicate-key one |
| INI duplicate sections/keys still accepted | no specification, and the de-facto standard splits — no verdict is claimed |
| A broken JSONL line reports a **line-relative** offset | diagnosability, not correctness |
