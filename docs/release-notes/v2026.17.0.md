# v2026.17.0 — release notes

## 0. One sentence — what this release is

**Three things the standards said and we did not do.** YAML 1.2's tags were dropped on the floor, TOML 1.0's
table rules were half-implemented (duplicate keys were refused, table redefinition was not), and the
serializer registry JSON and MessagePack have had all along was missing from the other three. The registry
adds nine public members, so this is `x+1` on the API rule as well as on behaviour.

## 1. YAML tags — a standard feature that was missing

A node's tag is part of the node. This reader discarded every one:

| Document | Before | Now | PyYAML |
|---|---|---|---|
| `Text: !!str 1` | `1` (number) | `'1'` | `'1'` |
| `Text: !!str null` | `null` | `'null'` | `'null'` |
| `Number: !!int "42"` | text `42` | `42` | `42` |
| `Text: !!null ""` | `''` | `null` | `None` |
| `A: !foo 1` | `1`, tag ignored | `FormatException`, naming the tag | `ConstructorError` |
| `- !!str 1` | the seven characters `!!str 1` | `'1'` | `'1'` |

The standard shorthands (`!!str`, `!!int`, `!!float`, `!!bool`, `!!null`, and the `!!map` / `!!seq` shape
checks) now apply, and each is pinned **line by line against PyYAML** — including where PyYAML itself is
quirky (`!!bool "1"` raises `KeyError` there; `!!null` swallows any content).

**Unknown and application tags throw instead of being ignored**, because a silently ignored tag is a value
the caller believes is typed. Application tag *handles* (`!myapp!`) still need a registration mechanism this
reader does not have — recorded as a separate feature rather than half-built.

## 2. TOML table redefinition — the other half of "defined twice"

2026.15.0 refused a duplicate **key**. A duplicate **table header** was still accepted. The spec's answer
depends on how the path came into existence:

| Path came from | `[T]` may appear again? |
|---|---|
| a table header `[T]` | no |
| an array of tables `[[T]]` | no — but `[[T]]` again is a **new element**, not a redefinition |
| a dotted key (`a.b = 1` created `a`) | no |
| a sub-table or super-table (`[T.S]`) | **yes, in either order** |

That last row is why a one-line check would have rejected valid documents: `[T]` then `[T.S]` and `[T.S]`
then `[T]` are both legal.

The eleven rows are pinned against `tomllib`, each message names its clause, and the **chunked path** agrees
with the buffered one across 22 shapes × chunk sizes 1, 2 and 3. That parity needed a journal the reader
carries in `TomlReaderState`, because `TomlSerializer.Step` builds a new reader per chunk — without the undo,
a chunked re-read of `[T]` would mistake its own earlier attempt for a redefinition.

## 3. `RegisterCustom<T>` for TOML, YAML and INI

JSON and MessagePack have had it all along; the other three had only `Register`. Now all five have
`RegisterCustom<T>`, `HasCustomSerializer<T>` and `SerializeCustom<T>`, backed by the same per-format
`SerRegistry`, and the three generators consult it in the **member**, **element** and **dictionary-value**
positions before their built-in path.

`SerializeCustom` is public for the same reason `JsonSerializer.SerializeCustom` is: generated code lives in
the consumer's assembly and cannot reach an `internal` member.

**Nine new public members** (+3 per package) — `api/PENDING-CHANGES.md` records them by member name, and
`-DryRun` reports `API changed: true`.

## 4. One consequence worth knowing

Every generated member now carries a `HasCustomSerializer<T>()` branch, so the probe baselines moved. That is
the only reason they moved, and it is visible in the diff.
