# v2026.14.1 — release notes

## 0. One sentence — what this release is

**No product behaviour changed except one new diagnostic.** This release is the fence-building that
followed an ablation of the whole repository: 58 mutations were applied one at a time to see which
protections any test actually watches, and the 18 that nobody watched are now covered.

That is why it is a `y` bump: the public API is untouched, no wire byte moved, and the only thing a
consumer can observe is one more warning in a build log for a document that could never have been read.

## 1. The method, because it is the point

An ablation breaks one protection at a time and asks whether the suite notices. Red means the protection
is pinned; **green means nobody is watching**. 58 mutations across five areas produced **40 red / 18
green**, and the 18 are what this release closes.

Two things the exercise taught, beyond the holes:

- **A filtered test run lies.** The first JSON mutation was run against the obviously-related test class
  and came back 13/13 green — nearly recorded as a hole. The full unit run failed six classes. The tests
  that watch a protection are usually not the ones named after it.
- **`--no-build` keeps the mutation alive.** Reverting the source and re-running without rebuilding leaves
  the mutated binary in place; one control run was wasted before this was spotted.

## 2. The one behaviour-visible change: `PICOSERDE008`

`IniWriter.WriteKey` writes a key verbatim, and nothing guarded the character set. Three `[IniKey]` values
were accepted with **no diagnostic and no exception**:

| `[IniKey]` | emitted | what a reader gets |
|---|---|---|
| `"n\nline"` | `n` newline `line = 8` | our own reader throws `FormatException` |
| `"[sec]"` | `[sec] = 8` | a **section header** — the member silently moves into an invented section |
| `"a=b"` | `a=b = 8` | every INI reader truncates the key to `a` |

The key is a **compile-time constant**, so this was answerable at generation time all along.
`PICOSERDE008` (Warning, `Location.None`, terminal — no reader can recover those bytes) now reports the
member, names the structural characters it found, and the member is dropped before any emitter sees it.
Section members and a top-level list's element members are keys too and take the same path.

`IniWriter` deliberately gets **no** runtime guard: by the time it runs, the wire shape is committed, so a
throw there could only refuse work the generator should never have emitted.

## 3. The fences, by area

| Area | What was unpinned | Now |
|---|---|---|
| `ScalarCodec` | `DateTimeOffset` round-trip pattern `"O"`→`"G"` (offset and sub-seconds lost) left 2317 tests green; `ParseHalf`'s range guard could be deleted | non-zero offsets, sub-second ticks and extremes; `"70000"` throws |
| TOML | the `NaN`/`Infinity` write refusal, on **both** paths (member and array element) | each path fenced separately, so knocking one out leaves the other's tests green |
| YAML | the write-side depth ceiling | both halves — what fits and the first thing that does not |
| JSON | a default-valued member could vanish (`Never` must write it) | artefact-level assertions per kind, plus a nested object |
| `PICOSERDE006` | disabling the descriptor **or** deleting its only report call left 1144 tests green | descriptor shape, report behaviour, pre-scan call site, wiring guard |
| `reopen:` | only 1 of 4 deferred templates was pinned | every deferred template must carry it |
| fused reader | `[,1]` answered `TryReadInt32` with `1` after the "give up and let `Read()` throw" retreat was deleted | malformed corpus × every fused member |
| YAML indented lists | the mapping-item layout (285 tests green while the bytes were wrong) | exact text, round trip, nested case, **and PyYAML reading those same bytes** |
| baseline gate | the gate itself could be made permanently green | a meta-test drives the comparison function directly: one byte changed must report one difference naming the file |
| `api-surface diff` | the `added=/removed=` line — the one `release.ps1` reads — could be hardcoded | tested as a process, reading both the line and the exit code |

**One correction worth recording:** the YAML indentation item was briefed as a writer defect. It was not.
The writer already emitted the right bytes; the ablation had mutated working code. The lane verified that
first and changed no product code, so this release moves no wire byte.
