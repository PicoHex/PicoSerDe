# v2026.14.0 — release notes

## 0. One sentence — what this release is

**Two generator defects reported from PicoActor are fixed — an `object?` member that never reached the
wire and a `[GenerateSerializer(typeof(PositionalRecord))]` that did not compile — and this is `x+1`
rather than `y+1` because one of them changes behaviour for code that used to run.**

## 1. `object?` members: the value was never written

Reported against `SagaCompleted(object? Result)`. Reproduced from the report first: serialising
`new WithObject("boom")` threw

```
FormatException: Cannot close object: property name was written with no value.
```

`JsonWriter` threw because the generated code wrote the property name and then an **empty block**:

```csharp
jw.WritePropertyName("Result");
if (value.Result != null)
{
}
else
    jw.WriteNull();
```

The cause is one missing arm, not a design limit: every generator has an any-value emitter (dispatch on
the runtime type: string / number / bool / object / array) and the **element** and **dictionary-value**
positions already used it. The **member** position had no `case "any"`, and a `switch` with no matching
case and no `default` emits nothing.

Write and read now go through that same chain, so `new WithObject("boom")` produces `{"Result":"boom"}`
and reads back as the string it was.

### 1.1 The other four formats

Asked whether the other formats shared the defect, we measured rather than assumed — a 5 × 3 table
(write non-null / write null / read back) per format:

| format | write non-null | read back | verdict |
|---|---|---|---|
| JSON | ❌ threw | ❌ | was broken |
| **MsgPack** | ⚠️ wrote `ToString()` text (a `long 42` travelled as `"42"`) | ❌ **silent null** (`case 1: break;`) | was broken |
| **INI** | ✅ | ❌ **silent null** (empty `else { }`) | was broken |
| YAML | ✅ but the generated member write put **CS8604** into code the consumer cannot edit | ✅ | warning only |
| TOML | ✅ | ✅ | not affected |

MsgPack and INI now use the same any chain their element and dict-value positions had, so **MsgPack
carries the type** instead of stringifying it. The null-member cells of TOML / YAML / INI are unchanged:
those formats omit a null member for every type, and each README already says so.

### 1.2 Two silences became loud

Both are deliberate and both are why this is `x+1`.

1. **The any-chain fallback used to stringify.** A runtime type the chain could not represent was written
   with `value.ToString()` — it left as a JSON string with no diagnostic, and read back as `String`. It
   now throws `FormatException` naming the runtime type and the offset. The input is a *value*, not a
   declaration, so no generation-time diagnostic can exist for it; the throw **is** the report.
2. **A member kind with no emitter is now `PICOSERDE006`.** Reported at build time (Warning,
   `Location.None`) instead of leaving a silent hole, and the arm throws `NotSupportedException` if
   anything still reaches it.

**Migration note:** if you serialize an `object`-typed member whose runtime type the any-chain has no form
for, you now get an exception instead of a string. That is the intended change; represent it with a
concrete type or a custom serializer.

## 2. `[GenerateSerializer(typeof(PositionalRecord))]` did not compile

```
error CS7036: There is no argument given that corresponds to the required parameter 'A' of 'PosRecord.PosRecord(string, int)'
error CS8852: Init-only property 'PosRecord.A' can only be assigned in an object initializer, ...
```

`[GenerateSerializer(typeof(T))]` is honoured by **all five** formats through one shared pipeline
(`GenPipeline` → `GenInfrastructure.ExpandAttributes`), which asked only "does it have a public
parameterless constructor and then emitted `new T()` plus init-only assignments. The **call-site**
pipeline asked a better question — it detected a record's primary constructor — so the same type worked
through `JsonSerializer.SerializeToUtf8Bytes<T>` and failed through the attribute.

Four copies of that detection are now one: `FindPrimaryConstructor` / `HasPrimaryConstructor` live in
`shared/Gen`, and the five generators plus the polymorphic expansion call them. `IsRecord` and
`IsImplicitlyDeclared` are no longer spelled anywhere else in the product.

A type that cannot be constructed at all is reported (**`PICOSERDE007`**, Warning, `Location.None`) and
dropped before any emitter sees it, so no format can emit `new T()` for it — `RegisterTypesOutput` takes
the format tag and reports for all of them, which is also why a future sixth format cannot forget.

## 3. Why `2026.14.0` and not `2026.13.4`

The spec's table separates what the API baseline can see from what it cannot:

| change | version |
|---|---|
| public API changed | `x+1` |
| public API unchanged, **behaviour tightened or loosened** | `x+1` |
| public API unchanged, **diagnostics only** | `y+1` |

The `api/*.public.txt` baselines are unchanged, but §1.2 is a tightening: code that used to stringify now
throws. §1.1 also changes MsgPack **bytes** for `object?` members (text → typed).

`next-version` gained `--bump auto|x|y` for exactly this case — `auto` still derives from `--api-changed`,
and `x`/`y` force the segment when the baseline cannot see the change. `release.ps1` passes it through as
`-Bump`.
