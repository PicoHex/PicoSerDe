# Release notes — 索引与约定

每个**已发布**的版本一个文件：`v<版本>.md`，文件名与 tag 一致。内容以 `scripts/release.ps1 -DryRun` 的
实际输出为唯一来源，不凭记忆写 delta。

## 索引

| 版本 | 文件 | 性质 | 跨包影响（同时引用兄弟包时） |
|---|---|---|---|
| `v2026.12.0` | [`v2026.12.0.md`](v2026.12.0.md) | **破坏性**（x bump，删 5 个枚举） | **有** —— 见该文件 **[第 5 节](v2026.12.0.md#5-跨包兼容同时引用兄弟包的消费者不是-drop-in)**（范例） |
| `v2026.11.0` | [`v2026.11.0.md`](v2026.11.0.md) | 纯增量（`+57 / -0`） | 无（公开面只加不减，兄弟包不需要重发） |

## 约定 1：破坏性版本必须同时列出**跨包影响**

只写"我的源码怎么改"是不够的。破坏性版本有两类受害者，断法完全不同：

| 受害者 | 断在哪 | 现有文档够不够 |
|---|---|---|
| 自己的源码引用本包 | **编译期**（`CS0246` / `CS0103`） | 迁移章节够 |
| **兄弟包**（按旧公开面编译、已发上 NuGet 的二进制） | **运行期**（`TypeInitializationException` → `MissingMethodException`），restore / build 全绿 | **必须单独写一节** |

第二类之所以必须单列：NuGet 的依赖声明里只有程序集版本，**没有任何元数据描述"这个包编译时面对什么公开面"**。
所以"两个包各自都装得上"与"两个包一起能跑"是两回事，而只有文档能把这个区别告诉消费者。

**判据很简单**：只要这次发布**删除了公开类型、或改了公开成员的类型/签名**，就必须有一节"跨包兼容"。
纯增量（`-0`）不需要，索引里写"无"即可。

## 约定 2：那一节必须写齐四个要素

缺一条就不算写清，因为四条对应消费者四个不同的问题：

| 要素 | 回答的问题 | 要求 |
|---|---|---|
| **症状** | "我看到的崩是不是这个？" | 贴**真实复现**的异常输出（异常类型 + 消息 + 关键栈帧），并说明**在哪个调用上炸**；写明"编译期无信号" |
| **受影响的包** | "谁需要重发？" | 逐包列出（含所在仓库），并给出**引用点 grep** —— 判据是"发布过的二进制 × 编译它时的版本"，不是"当前源码" |
| **判据** | "怎么一眼认出、别误诊？" | 编号清单，逐条可核对；**再列一个"不是这些"** 的表（容易混淆的相邻现象） |
| **迁移动作** | "我现在该做什么？" | **一行能照做的指引** + 组合矩阵（哪个版本配哪个版本可用/不可用），并给出检查传递依赖的命令 |

另外两条贯穿要求：

- **最低配套版本**要写成一个可执行的形状（例如 `[2026.12.0, )`），不要只写"建议升级"。
- **不要写反向承诺**。没实测过的组合不写"已验证可用"；写"未验证"或干脆不写。反例：在同一个文件里既说
  "运行期不兼容"，又说"已验证在旧版下可用"，读者只会信后者。

## 范例

[`v2026.12.0.md` 第 5 节](v2026.12.0.md) 是这一约定的第一个范例，四个要素的落点：

| 要素 | 在范例里的位置 |
|---|---|
| 症状 | §5.3 —— 实跑复现的 `TypeInitializationException` → `MissingMethodException` 全文（`PicoJetson 2026.12.0` + `PicoJsonRpc 2026.6.0`） |
| 受影响的包 | §5.2 —— `PicoJsonRpc`（`PicoNode`）需基于 `2026.12.0` 重发；附引用点清单与"命中 1 处"的 grep 结果 |
| 判据 | §5.3 —— 三条编号判据 + "不是这些"误诊表 |
| 迁移动作 | §5.5 —— "两个一起升，否则都别升" + 四格组合矩阵 + 检查传递依赖的命令 |

`v2026.12.0` 这一节还记了一条结构性结论（§5.4）：**开区间下界 `>= 2026.10.0` 挡不住这种不兼容**，
只能由兄弟包把下界抬到 `[2026.12.0, )` 后**重发**；而已发布版本里的旧下界改不了。这条结论对以后每一次
删类型/改签名都成立，写新一节时可以直接引用，不必重新论证。

## 其余约定

- **发版时写，不是发版前写**：`状态` 行要如实反映事实（已发布 / 草稿），并附可复核的证据（tag、nuspec 的
  `repository commit`、当前 `-DryRun` 输出）。发布状态变化时**回来改这一行**，别让它停在旧状态。
- **delta 一律标来源**：`api/*.public.txt` 基线只在 apply 步骤刷新；`-DryRun` 的 `API changed` / `next version`
  是版本号规则的唯一出处（`scripts/release.ps1`）。
- **仓库外的待办写进来**：兄弟包重发、skills 仓库改动这类本仓库改不到的事，在"遗留 / 开放项"里记一行，
  否则它会静默消失。
