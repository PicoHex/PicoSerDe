# v2026.14.2 — release notes

## 0. One sentence — what this release is

**The packages now carry two target frameworks.** Every library and every generator targets
`net10.0` **and** `net11.0`, so a consumer on .NET 11 gets a .NET 11 asset instead of a .NET 10 one.

No public API changed, no wire byte moved, and no behaviour changed. That is why it is a `y` bump:
`api/*.public.txt` is untouched and `release.ps1 -DryRun` reports `API changed: false`.

## 1. What a consumer sees

| Project kind | Before | Now |
|---|---|---|
| library (`PicoJetson`, `PicoIni`, …) | `net10.0` only | `net10.0`, `net11.0` |
| source generator (`*.Gen`) | `netstandard2.0` | `netstandard2.0` (unchanged — analyzers must stay loadable by every SDK) |
| test / benchmark projects | one TFM | `net10.0;net11.0` |

A project on `net11.0` now resolves the `net11.0` asset; a project on `net10.0` resolves exactly what it
resolved before. Nothing to migrate.

## 2. What else moved with it

- **`global.json` no longer pins an SDK version.** It pinned `10.0.201` with `rollForward: latestFeature`,
  which could not build a `net11.0` target at all; the file now lets the installed SDK be used.
- **CI pins the target framework on every `dotnet run`/`dotnet test`.** With multi-targeted test projects,
  an unpinned run either picks one framework silently or runs the suite twice — neither is a decision CI
  should make implicitly. Each leg states its framework.
- **Lock files were refreshed** for the new target (a multi-target project has one lock file covering both).
